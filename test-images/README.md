# test-images/ の構成ルールと運用

因子（継承）画面のスクリーンショットを置く場所。**画像結合ハーネス**（`tests/stitch/run-stitch-tests.mjs`）と
**OCRハーネス**（`tests/ocr/run-ocr-tests.mjs`）の両方が、ここから同じ形でケースを読む。
1つのサブフォルダ = **exam.html の「1人分」（親A/祖A1/祖A2 等）の画像1組**。

```
test-images/
  2026-09-16_1/          ← 直下のフォルダが「テスト対象のケース」
    IMG_3256.PNG
    IMG_3257.PNG
  2026-09-16_2/
    ...
  Archive/               ← 済んだケースの置き場。テストには回らない
    2026-09-15_1/
    2026-09-15_2/
  README.md
```

- ケース内の画像はファイル名の昇順で `stitchOnePerson()` に渡される（**アップロード順**として扱われる。
  実際の並び替えはアプリ側のスクロールバー検出ロジックが行うので、わざと実際のスクロール順と
  違う順番でファイルを置いてもよい）。
- 対応拡張子: `.png`, `.jpg`, `.jpeg`, `.bmp`, `.webp`
- 画像は実際にアプリが受け付ける形式に合わせる: 同一ケース内は**同じ幅**、かつ
  `exam.html` の `STITCH_KNOWN_SCREENSHOT_PROFILES`（DMM版/スマホ版相当のアスペクト比・幅の範囲）
  に収まっている必要がある。範囲外だとテスト対象の関数自体が「結合済み/加工済み画像の可能性」
  としてエラーを返す（これも正しい挙動としてレポートに表示される）。

## 運用の決まり（2026-09-16・47セッション目に決定）

### どのフォルダが回るか

**両ハーネスとも `test-images/` の直下のフォルダだけを見て、直下に画像ファイルが1枚も無いフォルダは飛ばす**
（`run-stitch-tests.mjs` / `run-ocr-tests.mjs` の `discoverCases()`）。
**ケース名はどのスクリプトにも書かれていない**し、**ケースを選ぶ引数も無い**（毎回、直下の全ケースが回る）。

したがって `Archive/` の中へ1段下げるだけで自動的に対象外になり、1段上へ戻せばまた対象に戻る。
**スクリプトの変更は要らない。**

### Archive に移す基準

**そのケースを使った報告が終わったら、次のセッションが始まる前に `Archive/` へ移す。**
下の「直下に残すもの」に当てはまるものだけを直下に残す。

理由: 直下に置いたままにすると毎回のテストがケース数に比例して伸びる
（目安: 1ケースあたり 結合 2〜3秒／OCR 10〜25秒。元画像と結合後の2通りを回すとその倍）。
**消さずに Archive へ移す**のは、あとから「あのときの画像」を取り直せるようにするため
（`20260910ライス` `20260912_シロエさんエル` `20260913-1〜6` は、この決まりが無かった時期に
ローカルから消えていて、`output/ocr/` に結果だけが残り再現できない）。

### 直下に残すもの（回帰素材）

次のどちらかに当てはまるものだけ、Archive に入れず直下に残す。

1. **製品コードの変更の根拠になった画像**（その画像でしか再現しない読み取りの問題を含むもの）
2. **画質ゲート・結合の境界条件の見本**（極端に幅が狭い・継ぎ目が弱い等）

直下に残すケースは、下の「現在のケース」の表に**なぜ残すか**を1行で書く。
**理由を書けないものは残さない。**

### ケース名の書き方

**`YYYY-MM-DD_N`**（撮影・受け取りの日付＋その日の連番）。区切りは `-` と `_`、連番は1から。

- ハーネスは名前を `localeCompare` で並べるだけなので、**書き方が揃っていないと一覧での並びが分かれる**。
- 人物名・ウマ娘名は付けない（個人の識別につながる情報を名前に残さないため）。
- `sample_*` は `npm run test:stitch:gen-samples` が作る合成ケースの予約名。実機の画像には使わない。

## 名前の食い違いについて

### 製品ファイルのコメントに残っているケース名

**製品ファイル（`js/` `css/` `*.html`）は、ケース名を変えるためだけには変更しない**（版の更新が要るため）。
そのため、次のコメントは**書かれた当時の名前のまま**になっている。いずれも**パスを開いてはいない**ので
動作には影響しないが、その名前のフォルダを探しても見つからないことがある。

| 場所 | 書かれている名前 | 現状 |
| --- | --- | --- |
| `js/common.js:42` | `test-images/20260912_シロエさんエル` | **現存しない**（Archive にも無い）。画質ゲートの足切りを 500px へ下げた根拠 |
| `js/common.js:345` | `test-images/2026-09-15_6` | **直下にある**（名前も一致） |
| `js/stitch.js:139` | `test-images/20260910ライス` ほか | **現存しない**（Archive にも無い）。継ぎ目検出を作り直した根拠 |

### `output/` 配下の結果フォルダ名との食い違い

`output/ocr/<ケース名>/` と `output/index.html` は**実行時のケース名で作られ、消されない**。そのため、

- **ケース名を変えると、古い名前の結果フォルダが残る**（次の実行では作られない）
- **Archive へ移したケースの結果も残る**（画像はもう回らないので更新されない）

`output/` は `.gitignore` 済みの使い捨てで、**古い結果は「そのときの記録」でしかない**。
紛らわしければ `output/ocr/` ごと消してよい（回し直せば作り直される）。
**古い名前の結果を、いまのケースの結果として読まないこと。**

## 個人情報・Git との関係

- **`Archive/` は必ず `test-images/` の中に置く。** `.gitignore` の `test-images/*` の1行が
  **配下すべてに効いている**ので、追加の設定なしで除外される
  （`git check-ignore -v test-images/Archive/<ケース>/<ファイル>` で `.gitignore:6` にヒットすることを確認済み）。
- **外に出すと覆われない。** `npm run check:privacy` は**追跡中のファイルだけ**を走査し、バイナリは飛ばすので、
  「未追跡だが未 ignore」の画像は誰も止めない。**画像に対する防壁は `.gitignore` の1行だけ**という前提で扱う。
- 素材フォルダ（正解付き素材＝C-24。`tests/skillset/lib/assets.mjs` の `assetsRoot()` 経由）とは別系統。
  **こちらは正解データを持たず、毎回まとめて回す場所**。精度を繰り返し測る素材は素材フォルダ側に置く。

## 実行方法

```bash
npm install                       # 初回のみ (Playwright)
npx playwright install chromium   # 初回のみ (ヘッドレスブラウザ本体)
npm run test:stitch               # 画像結合
npm run test:ocr -- --dict=deck   # OCR（445種のマスターで照合）
npm run test:ocr -- --dict=deck --stitched   # 結合してからOCR
```

`output/index.html` に、各ケースの「結合前（入力サムネイル一覧）」「結合後（結合結果 or
エラー）」「警告」「診断ログ」をまとめたレポートが生成される。
OCR の結果は `output/ocr/<ケース名>/result.json`（`rawLines` に**照合できなかった行も含めて全部**残る）。

このハーネスは exam.html を実際にヘッドレスブラウザで開き、中の `stitchOnePerson()` を
直接呼び出している（ロジックを複製していないので、exam.html 側の修正がそのままテスト結果に反映される）。

### シナリオ因子（追加カタログ）も照合したいとき

```bash
npm run test:ocr -- --dict=deck+catalog              # 445種 ＋ data/*.json
npm run test:ocr -- --dict=deck+catalog --stitched   # 結合してから
```

`+catalog` を付けないと、**シナリオ因子は写っていても検出されません**（辞書に無いため）。
後段の絞り込み（製品の `applyScenarioFactorStrictMatch()` と同じ＝完全一致か、24種の中で1つに絞れる1文字違い）は既定で掛かります。
詳しくは `tests/ocr/README.md` の「追加カタログ」の節。

## 実データが無い場合

```bash
npm run test:stitch:gen-samples
```

で、ハーネスの動作確認用に `sample_*` という合成テストケースを生成できる（実際のゲーム画面
ではなく、Canvas で描いた模擬画像）。それぞれ以下の観点を検証している:

| ケース名 | 検証する観点 |
| --- | --- |
| `sample_basic_overlap` | 3枚の素直な重なり結合（警告なしで正しく結合できるか） |
| `sample_shuffled_order` | アップロード順がバラバラでも、スクロールバー位置から正しい順序に復元できるか |
| `sample_low_confidence_seam` | 行の見た目が単調（実データで報告された「パネルが行によらず同じ形」）な場合に、継ぎ目の低信頼度警告が出るか |
| `sample_trailing_blank` | スクロールし過ぎて生じた末尾の空白領域が正しくトリミングされるか |
| `sample_reject_bad_size` | 標準的なスクリーンショットのサイズ範囲外の画像（結合済み/加工済み画像を誤アップロードしたケース）を弾けるか |
| `sample_single_image` | 画像が1枚のみの場合に適切なエラーになるか |
| `sample_width_mismatch` | 画像の幅が一致しない場合に適切なエラーになるか |
