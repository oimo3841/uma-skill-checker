# 恒久ルールの2か所の一致（check:rules）

```
npm run check:rules      # 単体で回す
npm run test:verify      # 納品前チェックの §8 からも走る
```

## 何を見ているか

恒久ルールは**同じ全文が2か所**にある。

| 場所 | 役割 |
|---|---|
| リポジトリ直下の `CLAUDE.md` | Claude Code が毎セッション自動で読む。`.gitignore` 済み（公開リポジトリなので追跡しない） |
| 同期フォルダの `CLAUDE-RULES.md` | 人が読む用・バックアップ用 |

この検査は、その2つが同じ内容かどうかだけを見る。

## なぜ2か所にあるか

参照で1か所にしたかったが、できなかった。2026-09-16 に実測した結果:

- `CLAUDE.md` から `@` でリポジトリ外の絶対パスを読み込む形は、区切りが `/` でも `\` でも展開されない
- フォルダのジャンクションを挟んだ相対パスでも展開されない（実体がリポジトリ外だと読まない）
- ファイルのシンボリックリンクは、この PC では作れない（開発者モード未設定・非管理者）。
  仮に作れても、Write / Edit のたびにファイルが置き換わってリンクが壊れる（ファイル ID の変化で確認）
- Git Bash の `ln -s` は**成功を名乗って実体のコピーを作る**ので、リンクのつもりで使ってはいけない

弱点は「2か所にあること」ではなく「**コピーし忘れても誰も気づかないこと**」。
そこだけを機械化したのがこの検査。

## 正本の場所の渡し方

**パスはリポジトリのどのファイルにも書かない**（恒久ルール12）。次の順に探す。

1. 環境変数 `UMA_CLAUDE_RULES`（`CLAUDE-RULES.md` の絶対パス）
2. リポジトリ直下の `.claude-rules.json`（`.gitignore` 済み）

```json
{
	"rulesFile": "<CLAUDE-RULES.md の絶対パス>"
}
```

画面に出すときは根を伏せて `<同期フォルダ>/CLAUDE-RULES.md` とだけ表示する。
`check-privacy.mjs` も、このパスとその**フォルダ名**を「追跡中のファイルに書いてはいけない文字列」として見ている。

## 落とすもの／警告にとどめるもの

| 状況 | 扱い | 理由 |
|---|---|---|
| 内容が一致しない | **NG** | この検査の存在理由。直すのはコピー1回 |
| `CLAUDE.md` が無い | **NG** | Claude Code が読むのはこれ。無い間は恒久ルールが1つも効いていない |
| 同期フォルダは見えるのに正本が無い | **NG** | 消えた・改名された＝実害 |
| 改行コードだけが違う | 警告 | 中身はズレていない。どちらがどの改行コードかを表示する |
| 同期フォルダの根が見えない | 警告 | Google ドライブ パソコン版が未起動・オフライン・別PC。変更の欠陥ではない |
| パスが未設定 | 警告 | clone 直後・CI を想定。`check-privacy.mjs` の `assetsRootOrNull()` と同じ方針 |

環境の都合で落とすと、変更と無関係な理由で push が止まる。
`check-privacy.mjs` と同じ理由でそれを避けている（偽陽性が出る設計では、警告が読まれなくなる）。

## 終了コード

**「落ちなかった」と「一致を確かめられた」は別物**なので、3値にしてある。

| コード | 意味 |
|---|---|
| `0` | 両方を読んで比べ、一致していた（改行コードだけの違いを含む） |
| `1` | 落とす（不一致・`CLAUDE.md` が無い・正本が無い） |
| `2` | 確かめられなかった（同期フォルダが見えない・パス未設定） |

`run-verify.mjs` の §8 は `2` のとき `[OK] 一致` とは出さず、`[--] 一致は確認できていない` と出す。
確かめていないことを「一致」と書くと、次に読む人が誤解するため。

## 不一致のときに出すもの

最初に違う行の行番号と両方の中身、行数、バイト数、更新日時。
更新日時から「どちらが新しいか」も出すが、**同期フォルダ側の更新日時は他の端末から同期で
降りてきたときにも変わる**ので、目安としてしか使えない。検査は自動では直さない。

## 状況を再現して確かめるには

```
node tests/rules/try-scenarios.mjs
```

**`test:verify` からは呼ばない。検査の中身を変えたときに手で回すもの。**
`runCheck({ repoFile, env, configFile })` に、一時フォルダのコピーと一時的な設定を渡して
7つの状況を再現する。**本番の `CLAUDE.md` / `CLAUDE-RULES.md` には触れない。**
一時フォルダは実行の最後に消える。全ケースが想定どおりなら終了コード 0、1つでも違えば 1。

再現するのは、上の表の6つ（不一致 / `CLAUDE.md` が無い / 正本が無い / 改行コードだけの違い /
同期フォルダが見えない / パス未設定）と、一致しているとき。
期待と実際を並べて出すので、変更で挙動が変わったかどうかが目で追える。
